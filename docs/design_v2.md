這是一個非常專業且具備可擴展性的「半自動化內容中台」架構。利用 Streamlit 作為 UI 層，配合 SQLite 存儲數據，可以完美實現你的需求。
以下是針對這個 「AI 頭條內容工作流」 的完整開發提示詞，你可以直接發送給 GPT-4 或 Claude 進行程式碼編寫：
------------------------------
🚀 開發需求提示詞：AI 中文頭條內容中台 (Streamlit + RSS + X API)
角色：
你是一位精通 Python 的全棧自動化專家，擅長使用 Streamlit 構建內容管理系統 (CMS)，並熟悉 X API v2 的計費與認證邏輯。
系統目標：
開發一個名為「AI 頭條發布工作站」的工具。實現：定時 RSS 抓取 -> 待選清單 -> 人工點選 -> AI 摘要預覽 -> 手動一鍵發布到 X。
核心功能模組要求：

   1. 資料抓取與存儲 (Ingestion & DB):
   * 使用 feedparser 定期從預設的 RSS 源（如 GitHub Trending, AI News RSS 等）抓取新聞。
      * 使用 SQLite 資料庫存儲：標題、連結、發布日期、狀態 (待處理/已跳過/已發布)。
      * 去重邏輯：資料庫需以 URL 為唯一鍵，確保不重複抓取。
   2. 管理後台 UI (Streamlit Interface):
   * 待選池頁面：以列表形式展示資料庫中「待處理」的新聞。每行有兩個按鈕：[選中摘要] 和 [跳過]。
      * 摘要加工區：點擊選中後，自動抓取網頁內容，調用 GPT-4o-mini 產生 3 個 Emoji 要點摘要（120字內）。
      * 編輯與預覽：提供一個 st.text_area 讓人工修改 AI 生成的摘要，並模擬 X 的發布視覺效果。
   3. 發布模組 (X API v2):
   * 點擊「🚀 立即發布」按鈕後，執行 OAuth 1.0a 認證發文。
      * 二段式發布：先發摘要主文，成功後自動回覆（Reply）該推文以附加原始連結（引流）。
      * 狀態更新：發布成功後，資料庫中的狀態改為 已發布。
   4. 計費監控 (Pay-per-use Tracking):
   * 在 Dashboard 顯眼位置顯示「今日發布次數」與「預計消耗餘額（$0.01/次）」。
   
技術細節：

* 庫需求：streamlit, requests_oauthlib, feedparser, openai, python-dotenv, sqlite3。
* 認證：所有 API Key 從 .env 讀取。
* UI 優化：側邊欄 (Sidebar) 放置 RSS 抓取按鈕和統計資訊。

交付要求：

* 包含 app.py（主程式）和 init_db.py（初始化資料庫腳本）。
* 程式碼需處理常見異常（如 RSS 超時、X API 403 權限拒絕）。

💡 給你的 1 期實施小撇步：

* RSS 源推薦：你可以先加入 Hacker News、Arxiv AI 或一些中文 AI 媒體的 RSS。
* 「人工选题」的妙處：在 Streamlit 列表裡，你可以快速掃視標題，只點擊那些你覺得「會爆」的內容。這比全自動發布更有「人情味」和「精確度」。
* 引流文章：在摘要區的範本裡，預設加上你自己的公眾號或網站引流語，手動確認時可以微調。
